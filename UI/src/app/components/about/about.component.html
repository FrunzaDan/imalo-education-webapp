About This Application

Imalo Education Webapp is a small full-stack learning project: an Angular single-page frontend talking to an ASP.NET Core Web API, which persists data in SQL Server through raw ADO.NET calls — no ORM, no stored procedures, just parameterized SQL commands.

Running It Locally

The database is a containerized SQL Server (Azure SQL Edge, which also runs natively on Apple Silicon), started by hand as: 

docker pull mcr.microsoft.com/azure-sql-edge

docker run -e "ACCEPT_EULA=1" -e "MSSQL_SA_PASSWORD=MyStrongPassw0rd?" -p 1433:1433 --name sqlserver --platform linux/arm64 -d mcr.microsoft.com/azure-sql-edge

Two scripts at the repository root wrap all of this so nothing needs to be pieced together by hand:

  • ./build.sh — restores and builds the .NET API, builds the SQL database project, then installs and builds the Angular app. Doesn't start anything; just proves everything compiles.
  • ./run.sh — the actual local dev environment. Starts (or reuses) the Azure SQL Edge container, deploys the database schema into it, then launches the API in the background and the Angular dev server in the foreground. Ctrl+C stops both.

Both the API and the Angular dev server must be running at the same time — the UI has no data of its own; everything it shows comes live from the API.

Database

The schema lives in its own SQL Server Database Project (a .sqlproj), not migration scripts. It has three tables:

  • Scholar — one row per scholar: name, school, grade, and birth date, keyed by a server-generated ScholarId (GUID).
  • ScholarPickupSchedule — one row per scholar, storing their Monday–Friday pickup times as a JSON blob.
  • ScholarAttendance — one row per scholar, storing every recorded day's lunch/transport cost and selection state as a JSON blob.

All reads and writes go through raw ADO.NET SqlCommands in ScholarDataAccess, with every input passed as a bound parameter — nothing is built by string-concatenating SQL.

No Authentication

Unlike a real production app, there's no login here — every API endpoint is open, and CORS accepts requests from any origin. That's a deliberate, appropriate choice for this project's current learning-project scope, not an oversight.

Console-Logged API Calls

Every HTTP call the Angular frontend makes to the API is mirrored to the browser's devtools console via apiLoggerInterceptor. Open devtools and watch the Console tab while using the app:

  • A blue → METHOD url line when a request goes out, with its body.
  • A green ← METHOD url status (Nms) line when the response comes back, with the response body and timing.
  • A red ✖ METHOD url status (Nms) line instead if the request fails.

What You Can Do In The UI
  • Browse the scholar table, sortable by name, school, grade, or birth date.
  • Create a new scholar, or edit an existing one, through a validated form.
  • View a scholar's details, including their pickup schedule.
  • Delete a scholar (with a confirmation prompt).
  • See every scholar's pickup times laid out on a day-by-day Gantt chart.
  • View and edit a scholar's monthly attendance, and save changes.
  • See every scholar's attendance at once on the Attendance dashboard.
  • Export the scholar table, the attendance dashboard, or a scholar's monthly attendance to CSV.
